# Explain attributeFilter performance discipline in depth.

> **Category:** DOM Advanced APIs | **Difficulty:** Medium | **Question #9723**

## Overview

Observing attributes across a large subtree forces the engine to diff every attribute of every descendant; attributeFilter: ["class", "style"] cuts the surface to named attributes only. Combined with omitting subtree when possible and unobserving once a goal is reached, filters turn potentially expensive watchers into negligible overhead.

Syntax: new MutationObserver(callback) creates the observer; observer.observe(target, options) starts watching; observer.disconnect() stops permanently; observer.takeRecords() drains pending records synchronously; observer.observe() may be called again after disconnect to restart.

Observation options: childList watches direct child additions/removals of target; subtree extends watching to all descendants; attributes watches attribute writes; attributeFilter narrows to specific names (["class", "style"]); characterData watches text-node data changes; attributeOldValue and characterDataOldValue populate record.oldValue with the prior value.

Callback payload: an array of MutationRecord snapshots, each carrying type ("childList" | "attributes" | "characterData"), target, addedNodes and removedNodes NodeLists, previousSibling and nextSibling for structural edits, attributeName plus optional oldValue for attribute writes, and oldValue for text edits when requested.

Delivery timing: records accumulate during a task and flush to your callback in a microtask, so you never observe half-finished DOM surgery, but also never fire synchronously inside the mutation itself. There is no initial callback on observe(), unlike intersection/resize observers.

Errors and gotchas: observing with none of childList/attributes/characterData throws; a callback that mutates what it observes re-triggers itself unless you disconnect-write-reobserve or guard with a flag; whole-subtree attribute watching on large trees costs measurable time, so filter aggressively; removed subtrees still deliver records captured before removal.

Practical tips: prefer unobserve(el) over disconnect when only some targets are done; drain takeRecords() right before teardown so final states are handled; frameworks render asynchronously, so observers are the reliable way to await mounted nodes instead of polling with setTimeout.

Member reference: observe(target, options) starts watching and REPLACES prior options when re-called on the same target; disconnect() stops all targets AND discards queued undelivered records; takeRecords() synchronously returns then empties pending records, letting you flush final state manually before teardown.

Common errors: TypeError when the options bag requests nothing watchable. Endless feedback loops when callbacks mutate observed nodes; break them with disconnect-write-reobserve or an applying flag. Performance cliffs from subtree-wide attribute watching on big trees; narrow with attributeFilter and minimal flags.

Gotchas and edge cases: removed subtrees still deliver records captured before removal. Framework renderers mutate asynchronously, making observers the reliable way to await mounted nodes versus setTimeout polling. Records are snapshots, safe to inspect after the fact. Multiple observers on one target each get independent batches; they never merge.

Browser support: every evergreen engine plus IE11, unprefixed; polyfills are unnecessary in modern code.

See also: IntersectionObserver for visibility, ResizeObserver for size, PerformanceObserver for metrics.

## Syntax & Examples

### map() - Transform

```javascript
const numbers = [1, 2, 3]
const doubled = numbers.map(n => n * 2)
// [2, 4, 6] - new array, same length
```

map() creates a new array with transformed values. Returns a new array.

### forEach() - Side Effects

```javascript
const numbers = [1, 2, 3]
numbers.forEach(n => console.log(n * 2))
// Logs: 2, 4, 6
// Returns: undefined
```

forEach() executes a function for each element. Returns undefined, used for side effects only.

### reduce() - Accumulate

```javascript
const numbers = [1, 2, 3]
const sum = numbers.reduce((acc, n) => acc + n, 0)
// 6 - single accumulated value
```

reduce() reduces array to a single value. Powerful for transformations, grouping, and computations.

## Reference Example

```javascript
const mo = new MutationObserver(rs => {
  const r = rs[rs.length - 1];
  if (r.type === 'childList') console.log('added:', r.addedNodes.length, 'removed:', r.removedNodes.length);
});
mo.observe(list, { childList: true });
list.append(document.createElement('li'));
```
