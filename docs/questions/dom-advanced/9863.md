# Show a practical example of using inspecting FormData entries.

> **Category:** DOM Advanced APIs | **Difficulty:** Medium | **Question #9863**

## Overview

FormData iterates [name, value] pairs (for (const [k, v] of fd)), and offers get(name) returning the FIRST match or null, getAll(name) returning every match as an array, plus keys()/values()/entries() iterators. Files appear as File objects in values. Object.fromEntries(fd) collapses duplicates to their LAST value, so only use it when names are guaranteed unique.

Construction: new FormData() builds an empty body programmatically; new FormData(formElement) harvests every ENABLED control that has a name (text inputs, textareas, selects, checkboxes/radios when checked, file pickers as File objects), mirroring native submission exactly, submit buttons excluded.

Entries model: ordered [name, value] pairs where value is string, Blob, or File. append(name, value, filename?) ADDS an entry permitting repeated names (server sees arrays); set(name, value) REPLACES all entries with that name guaranteeing singleness; get returns the FIRST match or null; getAll returns every match; has/delete operate across matches; keys/values/entries iterate including repeats.

Submission: pass the instance as fetch’s body and the platform generates Content-Type: multipart/form-data with a boundary; overriding that header manually corrupts the framing and servers reject the request. XHR send(fd) behaves identically.

Files: input[type=file] entries arrive as File objects; appending Blobs with a third filename argument renames uploads independently of blob.name, useful for normalized storage keys.

Gotchas: disabled or nameless controls vanish; unchecked checkboxes are ABSENT (not false); Object.fromEntries(fd) silently keeps the LAST duplicate and drops multiplicity, so collapse deliberately with your own reduction when repeated names exist; values serialize as strings, parse numbers explicitly.

Server trust: client MIME types and extensions are advisory; validate content properly server-side.

Member reference: append(name, value, filename?) adds (allowing repeats, filename renames Blob uploads); set(name, value) replaces all matches; get/getAll/has/delete as documented; keys/values/entries plus Symbol.iterator expose [name, value] pairs including duplicates.

Harvest rules detail: field sets from formElement include text inputs, hidden inputs, textareas, select options (selected ones), checked checkboxes/radios, and file pickers as File objects; disabled controls, those without name, and reset/submit buttons are excluded; image inputs contribute coordinates on native submits only.

Server interaction notes: fetch with a FormData body auto-computes multipart boundary headers, and manually overriding Content-Type is THE classic upload breaker; XHR behaves identically; servers should stream-parse large file parts rather than buffering whole bodies.

Conversion patterns: Object.fromEntries(fd) keeps only the LAST value per name, so build objects with explicit collision policy ([].concat accumulation for multi-values); [...fd] materializes pairs for Array pipelines; there is no built-in JSON serialization of files, POST the FormData directly instead.

See also: URLSearchParams for application/x-www-form-urlencoded bodies, the File and Blob interfaces, requestSubmit for validated programmatic submission.

Study the example above: it demonstrates the typical usage pattern and the pitfalls to avoid.

## Interactive Code Example

```javascript
const fd = new FormData();
fd.append('tag', 'a');
fd.append('tag', 'b');
console.log(fd.get('tag'));            // "a"
console.log(fd.getAll('tag'));         // ["a", "b"]
console.log(Object.fromEntries(fd).tag); // "b" (last wins)
```
