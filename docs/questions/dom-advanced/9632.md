# What common mistakes do developers make with theming shadow components with CSS custom properties?

> **Category:** DOM Advanced APIs | **Difficulty:** Hard | **Question #9632**

## Overview

Document-level styles cannot enter the shadow tree except through inherited properties and custom properties; expose --card-accent style hooks consumed inside shadow styles for sanctioned theming.

Creation: Element.attachShadow({ mode: "open" | "closed" }) returns the ShadowRoot; open exposes it via host.shadowRoot while closed severs outside access (mostly signaling intent, since composedPath still leaks internals). Only certain elements may host shadows, custom elements plus a documented HTML list (div, span, article, section, nav, body, etc.), and attaching elsewhere throws NotSupportedError.

Projection: light-DOM children render only where slots invite them. The unnamed slot catches unslotted children, slot="name" children route into matching named slots, and slot fallback content displays when projections arrive empty; assignedSlots/assignedNodes({ flatten: true }) inspect outcomes and slotchange fires when distribution changes.

Styling: document selectors cannot reach inside except via inherited properties; :host styles the host, :host(.x) conditions on host classes, ::slotted(el) targets top-level projected children only, and CSS custom properties intentionally pierce as the sanctioned theming channel, which is why design systems expose --token hooks.

Events: inside events retarget to the HOST for outside observers preserving encapsulation; composed events (focus, focusin, click, and most UI events) cross the boundary while others stop at it; composedPath()[0] recovers the deepest actual target regardless.

Gotchas: querySelector on the DOCUMENT will not find shadow internals, query the shadowRoot itself; getElementById likewise; DelegatesFocus option in attachShadow controls focus traversal; SSR renders no shadow content without client hydration.

Member reference: ShadowRoot inherits DocumentOrShadowRoot APIs (getSelection, activeElement, elementFromPoint scoped to the tree); host points back at its element; mode reads "open"/"closed"; delegatesFocus was an attachShadow option controlling focus traversal into the tree; slot elements inside carry assignedSlots/assignedNodes({flatten}) introspection.

Hostable elements: custom elements plus a fixed HTML list (article, aside, blockquote, body, div, footer, h1-h6, header, main, nav, p, section, span among others); attachShadow on void/media elements throws NotSupportedError, a frequent surprise with img/video wrappers.

Styling machinery recap: :host and :host(.class)/:host-context() style the host from within; ::slotted(selector) reaches ONLY top-level projected children, not their descendants; CSS custom properties and inherited properties are the sanctioned pierce-throughs; @host-context-style theming via data attributes on host stays the pragmatic convention; constructable stylesheets (adoptedStyleSheets) share style sheets across many shadow roots efficiently.

Debugging tips: DevTools shows shadow trees inline; document.querySelector will never find internals, query root.querySelector instead; event.target appearing as host while composedPath()[0] differs signals retargeting, not bugs.

See also: CustomElementRegistry for component registration, HTMLTemplateElement for inert markup factories, the CSS ::part() mechanism for styled extension points.
