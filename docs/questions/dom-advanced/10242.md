# Interview scenario — how would you describe ResizeObserver loop guards to a teammate?

> **Category:** DOM Advanced APIs | **Difficulty:** Medium | **Question #10242**

## Overview

Cache the last applied size and bail when the incoming contentRect matches within a pixel epsilon; this single comparison eliminates the deferred-loop error triggered by canvases or labels that grow their own container.

Syntax: new ResizeObserver(callback) then observe(target, options?) where options.box selects "content-box" (default), "border-box", or "device-pixel-content-box"; unobserve and disconnect round out the API.

Entry payload: contentRect is a DOMRectReadOnly of the CONTENT box in CSS pixels; borderBoxSize / contentBoxSize / devicePixelContentBoxSize are ARRAYS of { inlineSize, blockSize } (fragmented boxes yield multiple rows, read [0]), with devicePixelContentBoxSize giving exact physical pixels for crisp canvas backing stores under fractional devicePixelRatio.

Timing: callbacks run after layout but BEFORE paint, and fire once initially per element, making them safe places to resize canvases or re-measure charts without visible flicker.

The loop problem: resizing an element that the observer also observes defers extra cycles; browsers eventually report "ResizeObserver loop completed with undelivered notifications" as a benign window error. Guard by caching last-applied sizes and skipping sub-pixel-identical writes, or move measurement targets out of mutated subtrees.

Gotchas: contentRect excludes padding and border (use borderBoxSize when you need the outer box); display:none elements report zero sizes; transitions animate size continuously, flooding callbacks, so throttle or observe a stable wrapper instead; SVG elements observe their viewport box, which surprises.

Why not window.onresize: resize fires only for viewport changes, while ResizeObserver catches flex/grid redistribution, sidebar collapse, font swaps changing intrinsic width, and programmatic style writes, letting components own their responsiveness locally.

Member reference: observe(target, options?) attaches a target (re-observing updates its box option); unobserve(target); disconnect(); callback signature mirrors other observers as (entries, observer).

Box semantics detail: inlineSize/blockSize follow writing modes, so vertical-text layouts swap their meaning; devicePixelContentBoxSize stays Chromium-only today, feature-detect via entry.devicePixelContentBoxSize !== undefined and fall back to Math.round(contentRect.width * devicePixelRatio) elsewhere.

Interaction with CSS: contain layout/paint on observed subtrees reduces invalidation scope; transitions animating width/height fire the observer every frame, so throttle reactions, transition transform-only properties, or observe a non-animated wrapper instead.

Browser support: shipping everywhere since 2020; resize-observer-polyfill covered older WebKit via MutationObserver plus rAF polling.

See also: IntersectionObserver for visibility, matchMedia for viewport conditions.
