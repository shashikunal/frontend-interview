# What is sorting query params for stable identity?

> **Category:** DOM Advanced APIs | **Difficulty:** Easy | **Question #10016**

## Overview

sort() orders entries alphabetically by name, canonicalizing URLs whose param order varies (analytics dedupe, cache-key normalization, signature computation). Call it before toString()/href comparison to decide whether two URLs are semantically equal regardless of insertion order.

Construction: from a query string ("a=1&b=2", a LEADING "?" is tolerated), a plain object ({ page: 2 }), an iterable of [name, value] pairs, another instance, or empty; values stringify shallowly so nested structures need explicit flattening first.

Reading: get(name) returns the FIRST value or null; getAll(name) returns every value in insertion ORDER as an array (empty when missing); has(name) tests existence; repeated keys come from multi-selects, tag inputs, and arrays-by-repetition conventions, so parsers must use getAll or truncate silently.

Writing: append ADDS a repeat, set REPLACES all matches with one, delete removes ALL entries for the name, sort() orders entries alphabetically canonicalizing URLs for cache keys, dedupe, and signatures, and size (modern engines) counts entries.

Iteration: for (const [k, v] of params) visits EVERY entry including repeats; spreading into Map or Object.fromEntries collapses duplicates last-wins, losing multiplicity by design.

Encoding: application/x-www-form-urlencoded rules apply, spaces encode to "+", reserved characters (&, =, #, %) percent-encode, unicode encodes as UTF-8; decoding reverses it, and "+" decodes back to space, which is why raw pluses in data must be pre-encoded.

Interplay: url.searchParams stays synchronized with url.search in both directions; building URLs by mutating params beats concatenation every time; when serializing standalone remember toString() omits the "?".

Member reference: size (modern engines) counts entries; forEach mirrors Map signature; entries()/keys()/values() return iterators honoring multiplicity; toString() re-encodes WITHOUT a leading "?", prepend manually when building hrefs from scratch.

Encoding corner cases: "+" decodes to space on read while literal "%2B" survives as plus; constructing from location.search is safe because a leading ? is tolerated; double-encoding bites when already-encoded strings pass through again, decode-once policies prevent %2520 artifacts.

State management patterns: clone then mutate (new URLSearchParams(current)) to compute next-page links without touching live state; diff old versus new param maps after popstate to decide rerenders; sort() before comparison makes order-insensitive equality checks trivial.

Framework interplay: router libraries parse once into typed objects at route entry; direct USP usage suits vanilla apps; remember searchParams changes do NOT fire any event, history integration is manual via pushState/replaceState.
