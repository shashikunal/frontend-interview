# How would you describe URL relative resolution and errors to a teammate?

> **Category:** DOM Advanced APIs | **Difficulty:** Medium | **Question #9987**

## Overview

new URL("/api/v2", "https://api.example.com/v1") resolves relatives exactly like a browser would (protocol-relative, ../, ./ all honored), while missing base for a relative string throws TypeError, so constructors double as strict validators. Catch and fall back rather than letting malformed user links crash form handlers or redirect builders.

Construction: new URL(url, base?) parses strictly, THROWING TypeError on invalid input (including missing base for relative strings), which doubles as a validator; relative references resolve exactly like browser navigation, honoring protocol-relative "//host", "../", and "./".

Decomposition: readable/writable href, origin, protocol, username, password, host (hostname:port), hostname, port, pathname, search, hash, plus searchParams. Assignments re-serialize href with canonicalization: default ports drop (443/80), spaces percent-encode, pathname gains its leading slash.

Query handling: url.searchParams is a live URLSearchParams view synced BOTH ways with search; mutate params through it rather than string concatenation, which breaks on ampersands, equals signs, and unicode.

Validation and safety: parsing proves WELL-FORMEDNESS, not safety, javascript: and data: URLs parse happily, so scheme-allowlist before navigation, iframe assignment, or redirects; origin is null for opaque schemes like file: and data:.

Modern additions: URL.canParse(input, base?) returns a boolean without exceptions where supported; url.toJSON/toString mirror href.

SPA patterns: build filter/pagination URLs by cloning and mutating, then history.pushState/replaceState(null, "", u.href) to mirror state in the address bar without reloads; popstate restores views from parsed URLs on back-navigation.

Member reference: canParse(input, base?) (modern) tests validity without exceptions; url.toJSON/toString equal href; static URL.createObjectURL(blob)/revokeObjectURL manage blob links; instance properties username/password/port round out full credential handling, all normalized on write.

Normalization deep dive: assigning pathname percent-encodes spaces and control chars; port assignment accepts "" to clear back to scheme default; hash keeps its # on read but tolerates missing # on write; protocol requires the trailing colon ("https:") while assignments like "http" throw SyntaxError.

Security playbook: parsing proves structure only, javascript:/data: URLs are well-formed attacks-in-waiting; allowlist schemes before location assignment, iframe src, or anchor clicks; prefer origin comparisons over string href equality for trust decisions.

Interop notes: Location (window.location) exposes the same property surface for the current document and accepts identical mutations; history.pushState/replaceState accept URL-serialized strings; Service Workers parse Request URLs through this same interface.

See also: URLSearchParams for query editing, Location for the current document URL, History for session manipulation.
