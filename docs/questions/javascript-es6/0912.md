# Explain for-in pitfalls with inherited props in depth.

> **Category:** JavaScript & ES6 | **Difficulty:** Medium | **Question #912**

## Overview

for-in walks the whole enumerable prototype chain, so library-augmented Object.prototypes leak into loops — historically guarded by hasOwnProperty filters. Modern practice avoids for-in for data entirely: Object.keys/values/entries iterate own keys deterministically (string-keyed insertion order; integer-like keys ascending).
