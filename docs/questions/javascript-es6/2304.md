# Interview scenario — how would you describe the event loop to a teammate?

> **Category:** JavaScript & ES6 | **Difficulty:** Medium | **Question #2304**

## Overview

The event loop repeatedly takes the oldest runnable task from task queues, runs it to completion, then drains the entire microtask queue (promise reactions, queueMicrotask, MutationObserver) before rendering and picking the next task. This single-threaded cooperative model explains why tight loops freeze UIs and why microtasks starve timers if chained forever.

## Key Concepts

- Promise states: pending, fulfilled, rejected
- Promise chaining with .then() and .catch()
- Promise.all(), Promise.race(), Promise.allSettled()
- Call stack
- Task queue (macrotasks)
- Microtask queue
- Event loop tick
- Call-site binding
- Implicit, explicit, new, and default binding
- Arrow function lexical this

## Syntax & Examples

### Event Loop Order

```javascript
console.log('1')

setTimeout(() => console.log('2'), 0)

Promise.resolve().then(() => console.log('3'))

console.log('4')

// Output: 1, 4, 3, 2
```

Synchronous code runs first, then microtasks (Promise), then macrotasks (setTimeout).
