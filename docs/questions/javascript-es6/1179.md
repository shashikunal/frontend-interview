# What does lazy initialization patterns look like in practice, and when does it matter?

> **Category:** JavaScript & ES6 | **Difficulty:** Medium | **Question #1179**

## Overview

Lazy getters defer expensive construction until first access: function heavy(){ if(!cache) cache = compute(); return cache }. Memoized thunks export pre-computed promises kicking work early without blocking import. Lazy route/component loading extends the idea to code itself via dynamic import.

## Key Concepts

- Promise states: pending, fulfilled, rejected
- Promise chaining with .then() and .catch()
- Promise.all(), Promise.race(), Promise.allSettled()
