# Whiteboard prompt: What common mistakes do developers make with Object.is vs === edge cases?

> **Category:** JavaScript & ES6 | **Difficulty:** Easy | **Question #3300**

## Overview

Object.is(NaN, NaN) is true and Object.is(+0, -0) is false — exact opposite of === on those edges — otherwise identical semantics. Useful in equality helpers, React’s comparison discussions, and numeric algorithms distinguishing signed zero. Everyday code rarely needs it but interviews probe the distinction.

## Key Concepts

- Strict equality (===) vs loose equality (==)
- Type coercion in JavaScript
- Abstract Equality Comparison Algorithm
- Strict Equality Comparison Algorithm

## Syntax & Examples

### Loose Equality (==)

```javascript
// Type coercion occurs
5 == "5"        // true
null == undefined  // true
0 == false      // true
"" == 0         // true
"0" == false    // true
```

Loose equality converts both operands to the same type before comparing. This can lead to unexpected results.

### Strict Equality (===)

```javascript
// No type coercion
5 === "5"       // false
null === undefined  // false
0 === false     // false
"" === 0        // false
"0" === false   // false
```

Strict equality compares both value and type without conversion. This is the recommended approach.

### Best Practice

```javascript
// Always prefer ===
if (value === expected) { ... }
if (userInput === "yes") { ... }

// Use Object.is() for special cases
Object.is(NaN, NaN)        // true (=== returns false)
Object.is(0, -0)           // false (=== returns true)
```

Use strict equality by default. Object.is() handles edge cases like NaN and ±0.

## Additional Examples

### Real-world Bug Prevention

```javascript
// BAD: Unexpected coercion
function isActive(user) {
  return user.status == "active" // "1" == "active" -> false, but 1 == "1" -> true
}

// GOOD: Explicit comparison
function isActive(user) {
  return user.status === "active"
}

// Type-safe API response handling
function parseResponse(data) {
  if (data && typeof data === "object" && "id" in data) {
    return data
  }
  throw new Error("Invalid user data")
}
```

Using === prevents subtle bugs from type coercion, especially with API data.
