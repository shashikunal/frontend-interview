# Quick check: what common mistakes do developers make with the classic closure-in-a-loop problem?

> **Category:** JavaScript & ES6 | **Difficulty:** Easy | **Question #4262**

## Overview

Using var in a loop shares one binding, so callbacks scheduled asynchronously all see the final value. Using let creates a fresh binding per iteration, so each callback captures its own copy. Alternatively wrap the body in an IIFE that takes the index as a parameter to force a new scope.

## Key Concepts

- Lexical scoping
- Function returning function
- Captured variables

## Syntax & Examples

### Basic Closure

```javascript
function outer() {
  const secret = "hidden"
  return function inner() {
    return secret // accesses outer scope
  }
}

const getSecret = outer()
console.log(getSecret()) // "hidden"
```

Inner function retains access to outer function scope after outer returns.

### Closure in React (useState)

```javascript
function Counter() {
  const [count, setCount] = useState(0)

  const handleClick = () => {
    setCount(c => c + 1) // closure captures latest count
  }
  // ...
}
```

React hooks use closures to capture state values. Functional updates avoid stale closures.
