# What does IndexedDB transactional shape look like in practice, and when does it matter?

> **Category:** DOM & Web APIs | **Difficulty:** Hard | **Question #9405**

## Overview

indexedDB.open(name, version) triggers upgradeneeded for schema creation; operations run inside IDBTransactions (readonly/readwrite modes scoping object stores) whose complete/error events gate success; IDBObjectStore put/get/getAll/delete/index queries return IDBRequests resolving asynchronously. All async surfaces also ship promise wrappers (indexedDB.withTransactionStyle libs or native in modern engines).

## Key Concepts

- Promise states: pending, fulfilled, rejected
- Promise chaining with .then() and .catch()
- Promise.all(), Promise.race(), Promise.allSettled()
