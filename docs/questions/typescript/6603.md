# Deep dive: What common mistakes do developers make with this parameter typing?

> **Category:** TypeScript | **Difficulty:** Easy | **Question #6603**

## Overview

Explicit this: Type annotates expected contexts catching lost-this bugs in standalone functions; this is void forbids this usage entirely. noImplicitThis enforces awareness. Arrow methods inherit enclosing this types lexically sidestepping most manual annotation ceremony.

## Key Concepts

- Call-site binding
- Implicit, explicit, new, and default binding
- Arrow function lexical this

## Syntax & Examples

### this Binding Rules

```javascript
// Default binding
function foo() { console.log(this) }
foo() // window (or undefined in strict)

// Implicit binding
const obj = { foo: function() { console.log(this) } }
obj.foo() // obj

// Explicit binding
foo.call(obj) // obj

// new binding
new foo() // new instance

// Arrow function (lexical)
const arrow = () => console.log(this)
arrow() // enclosing scope's this
```

this is determined by how a function is called (call-site), not where it's defined. Arrow functions inherit this lexically.
